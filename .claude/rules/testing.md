# 测试规则

> 本文只管**测试的写法与命名约定**。各套件覆盖什么见 `AGENTS.md` §开发命令，
> 逐类断言要点见 `docs/development.md` §测试规范；不要在这里再抄一份清单（旧版的覆盖列表已经落后于实际套件）。

- **测试文件位置**: 所有测试文件放在 `tests/` 目录中
- **测试命名**: 新测试用 `.test.mjs` 后缀，按被测面拆分（棋盘 / 棋型 / 战术 / 增量 / 自对弈 / 协议）；历史文件 `tests/test.mjs` 保留原名
- **测试结构**: 单元类套件分组标题用 `Test N:`；协议/冒烟类套件（workers / server / selfplay）可用 `=== 章节 ===` + 断言列表，与现有风格一致
- **运行方式**: `npm test` 跑全部（提交前置条件）；单跑用 `node tests/<文件名>.mjs`
- **接入脚本**: 新增测试文件必须加进 `package.json` 的 `test` 脚本，否则不会被执行
- **文档口径**: 文档里描述测试规模只用**用例数**，不写断言条数（断言数每次加用例都会腐烂）
- **测试数据**: 使用有意义的测试数据，覆盖典型场景和边缘情况
- **断言**: 测试应有清晰的通过/失败输出，方便调试
- **手动测试**: 浏览器中验证 UI 响应性、AI 对战表现；在线对战用两个标签页验证建房/加入/同步/重开换先/断线重连
